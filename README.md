# Решение тестового задания: Интернет-магазин и оформление заказа

Фронтенд-приложение на React 19, TypeScript и Vite, расположенное в `apps/web` (`@checkout/web`), полностью интегрированное с локальным REST API магазина.

Репозиторий решения: [https://github.com/ArtemChik103/frontend-checkout-challenge](https://github.com/ArtemChik103/frontend-checkout-challenge)

---

## Быстрый запуск

### 1. Установка зависимостей

Требуются Node.js >= 24.x и pnpm (или npm >= 11.x).

```sh
pnpm install
```

_(или `npm ci` / `npm install`)_

### 2. Запуск в режиме разработки

Для запуска бэкенда (порт 4000) и фронтенда (порт 5173):

```sh
# Терминал 1: запуск API сервера
pnpm run dev

# Терминал 2: запуск веб-приложения
pnpm run dev:web
```

Фронтенд доступен по адресу: [http://localhost:5173](http://localhost:5173).
Swagger API: [http://localhost:4000/docs/](http://localhost:4000/docs/).

### 3. Сборка и проверки

```sh
# Проверка типов и сборка фронтенда
pnpm run build:web

# Полная проверка проекта (линтер, OpenAPI спецификация, тесты бэкенда)
pnpm run check

# Запуск smoke-тестов API (при работающем бэкенде)
pnpm run smoke
```

## Устройство работы с API и распределение обязанностей (DRY & Обобщение — D1–D8)

Все сетевые взаимодействия спроектированы в соответствии с высокими стандартами обобщения кода: в React-компонентах **полностью отсутствуют** прямые вызовы `fetch`, ручные проверки `response.ok`, `response.json()` или дублирующиеся блоки `try/catch`.

### Архитектурные уровни:

1. **Единый HTTP-транспорт (`apps/web/src/lib/api-client.ts`)**:
   - **Централизация конфигурации (D1, D2)**: Базовый адрес API, системные заголовки (`Accept: application/json`, `Content-Type`), токены авторизации (`Authorization: Bearer <token>`) и заголовки идемпотентности (`Idempotency-Key`) формируются в едином клиенте `ApiClient`.
   - **Корректная обработка ответов без тела (D3)**: Статусы `204 No Content` и `304 Not Modified` обрабатываются без вызова `response.json()`, что исключает ошибки синтаксического анализа.
   - **Единая нормализация ошибок (D4, D8)**: Любые сбои (сетевые разрывы, некорректный JSON, HTTP-коды 4xx/5xx, ошибки отмены `AbortError`) преобразуются в строго типизированный объект `AppError`:
     ```ts
     export interface AppError {
       readonly kind: 'http' | 'network' | 'parse' | 'abort';
       readonly status?: number;
       readonly code?: string;
       readonly message: string;
       readonly fields?: ReadonlyArray<{ readonly path: string; readonly message: string }>;
       readonly requestId?: string;
     }
     ```
   - Компоненты получают либо готовые данные с гарантированными TypeScript-типами из `@checkout/contracts`, либо нормализованную ошибку.

2. **Обобщенный механизм опроса (`apps/web/src/lib/poll.ts`) (D5)**:
   - Функция `pollUntil<T>` инкапсулирует логику асинхронного ожидания, поддержку заголовка `Retry-After`, прерывание по `AbortSignal` при размонтировании компонента или уходе со страницы.
   - Исключает дублирование циклов проверки статуса платежа.

3. **Валидация и трансформация данных (`apps/web/src/lib/validation.ts`, `format.ts`) (D6)**:
   - Единые функции валидации email, телефона (`^\+[1-9]\d{9,14}$`), адреса и привязки серверных ошибок `path` к полям ввода формы (`extractFieldError`).
   - Единое форматирование копеек в рубли через `Intl.NumberFormat`.

4. **Обобщенные компоненты интерфейса (`apps/web/src/components/common/`) (D7)**:
   - `FormField`: доступная разметка (связка `label`, `input`, `id`, `aria-describedby`, `aria-invalid`, подсветка ошибок).
   - `Button`: автоматическое отображение спиннера, блокировка повторного нажатия (`aria-busy`), предотвращение race conditions при двойном клике.
   - `Alert`, `Modal`: переиспользуемые контейнеры состояний с поддержкой клавиатуры (`Escape`, фокус).

## Разбор участка обработки данных и производительность (P1, P2)

### Исследуемый участок: `processCartSinglePass` (`apps/web/src/lib/data-processing.ts`)

```ts
export function processCartSinglePass(
  items: ReadonlyArray<CartItem>,
  productsMap: ReadonlyMap<string, Product>,
): CartSummary {
  const len = items.length;
  let totalQuantity = 0;
  let subtotalKopecks = 0;
  const outOfStockIds: string[] = [];
  const itemMap = new Map<string, CartItem>();

  for (let i = 0; i < len; i++) {
    const item = items[i];
    totalQuantity += item.quantity;
    subtotalKopecks += item.lineTotal;
    itemMap.set(item.productId, item);

    const product = productsMap.get(item.productId);
    if (product && item.quantity > product.stock) {
      outOfStockIds.push(item.productId);
    }
  }

  return { totalQuantity, subtotalKopecks, outOfStockIds, itemMap };
}
```

### Анализ эффективности:

1. **Частота вызова**:
   Функция вызывается при каждом обновлении корзины (добавление, изменение количества, удаление позиции), а также при первичном получении данных каталога. В React мемоизирована через `useMemo`, предотвращая лишние запуски при несвязанных рендерах.
2. **Число проходов (ровно 1 проход)**:
   - В наивной реализации разработчики часто пишут цепочки:
     ```ts
     // ПЛОХО: 4 прохода по массиву, создание 3 промежуточных массивов
     const totalQuantity = items.map((i) => i.quantity).reduce((a, b) => a + b, 0);
     const subtotal = items.map((i) => i.lineTotal).reduce((a, b) => a + b, 0);
     const outOfStock = items.filter(
       (i) => i.quantity > products.find((p) => p.id === i.productId).stock,
     );
     ```
     Подобный наивный код имеет алгоритмическую сложность $O(N \cdot M)$ из-за вложенного `products.find`, делает 4 прохода по массиву и аллоцирует промежуточные массивы в куче.
   - Наше решение выполняет **ровно 1 проход $O(N)$** в плотном цикле `for`, одновременно вычисляя количество, сумму, индексируя позиции в `Map` для мгновенного доступа по ID за $O(1)$ и выявляя товары с превышением остатка.
3. **Выделение памяти и работа сборщика мусора (GC)**:
   - Создается ровно одна коллекция `Map` и один компактный массив `outOfStockIds` только при наличии нарушений.
   - Отсутствует квадратичный спред `{ ...acc, [id]: item }` внутри `.reduce()`, приводящий к лавинообразному созданию промежуточных объектов в памяти ($O(N^2)$ аллокаций).
4. **Особенности оптимизатора V8**:
   - Массив `items` сохраняется как плотный упакованный массив (`PACKED_ELEMENTS`).
   - Исключено использование оператора `delete array[i]`, который переводит внутреннее представление массива V8 в разреженный режим с дырками (`HOLEY_ELEMENTS`), лишая движок возможности применять быстрые векторные инструкции и inline-кэши.
   - Каталог товаров предварительно индексируется функцией `indexProductsById` в `Map` за один проход $O(M)$, обеспечивая $O(1)$ время выборки свойств товара.

## Проверенные сценарии

- [x] **A1. Каталог и корзина**: Загрузка каталога с сервера; добавление товара через `PUT /api/cart/items/{id}`; абсолютное изменение количества (+/-) с проверкой серверного остатка; удаление товара через `DELETE`; очистка корзины.
- [x] **A2. Оформление и расчет (Quote)**: Ввод имени, email и телефона; выбор самовывоза с выбором ПВЗ; выбор курьерской доставки с адресом; расчет стоимости доставки через `POST /api/quotes` (бесплатно при сумме от 5 000 ₽); обновление расчета при изменении состава корзины.
- [x] **A3. Онлайн-оплата картой**: Заказ создается с уникальным `Idempotency-Key`; открытие модального окна оплаты; выбор тестовой карты из Sandbox API (`GET /api/sandbox`); симуляция платежа; опрос статуса через `pollUntil` с учетом задержки; проверка итогового статуса заказа `paid / succeeded`.
- [x] **A4. Заказ с оплатой при получении & Страница успеха**: Заказ с `cash_on_delivery` сразу получает статус `confirmed / unpaid` без онлайн-оплаты; страница успеха отображает номер заказа, состав товаров, адрес/ПВЗ доставки и итоговую сумму.
- [x] **B1. Обработка отказа и отмены карты**: Имитация сценариев `decline` (`CARD_DECLINED`) и `cancel`; сохранение заказа с возможностью повторной оплаты; генерация нового `Idempotency-Key` для каждой новой попытки оплаты.
- [x] **B2. Восстановление сессии и заказа**: Сохранение токена гостевой сессии и `active_order_id` в `localStorage`; корректное восстановление при перезагрузке страницы; остановка опроса статуса при закрытии окна или размонтировании (`AbortController`).
- [x] **B3. Конфликты версий корзины**: Обработка ошибок `409 CART_VERSION_CONFLICT` и `409 QUOTE_EXPIRED` с автоматическим обновлением корзины и запросом свежего расчета без потери введенных данных пользователя.
- [x] **B4. Валидация и пустая корзина**: Блокировка перехода к чекауту при пустой корзине; подсветка ошибок валидации полей; сохранение черновика формы при сетевых сбоях.
- [x] **C1. Интерфейс и адаптивность**: Адаптивная верстка, проверенная на разрешениях 1280px (десктоп) и 390px (мобильный); доступность с клавиатуры (Tab, Enter, Space, Escape для модального окна).
- [x] **E1. Сборка и зависимости**: Чистая установка через `pnpm install`, успешная сборка TypeScript и Vite (`pnpm run build:web`), прохождение всех тестов бэкенда (`pnpm run check`).
